# Development Knowledge Preservation

This is the evidence ledger for sonic decisions that cannot be recovered from parameter values alone. It does not change the web product or approve a Standalone implementation. The current state is **capture framework ready; reference recordings, controlled listening results, and performance measurements pending**. Do not fill a result from recollection or infer listening approval from a numerical test.

For every completed entry, record: **WHAT changed, WHY, HOW it affects the sound, and WHAT a Standalone version must preserve**. Keep old and new values, including rejected approaches. Link a reproducible setting/curve snapshot or describe all points and controls explicitly; a screenshot alone is insufficient.

## Curve and Gesture Listening Matrix

### 2026-10-02 Resynthesis cutoff listening result

The user reported crackle around 2 kHz Base Freq with 64 analyzed partials, without obvious output clipping. The screenshot showed a low detected peak near 84 Hz and a partial near 1003 Hz; at 48 kHz that partial reaches the old 23,040 Hz hard cutoff around 1.93 kHz Base Freq. The old renderer omitted it immediately, stopped its phase, and changed normalization as the active set changed. After adding a smooth 0.42-to-0.48-rate fade and continuous phase advance for silent partials, the user reported that the problem disappeared and asked to keep the change. The original `test.wav`, precise curve coordinates, device and listening level were not provided for independent replay. This supports the correction for the reported case, not a universal anti-aliasing claim. See D-014.

The code evaluates smoothstep between ordered normalized points at audio-frame time. Deviation and modulation amount additionally receive short mapped-value audio slews; Base Freq and Slope do not. A short segment can still traverse a large change rapidly even though its endpoints ease. The audible consequence is a **test question**, not a verified click or aliasing finding.

## 2026-10-01 Clarity Investigation (Listening Pending)

The user reported steadier level and fewer broken peaks but less high-frequency clarity. A matched-level dry comparison of the previous committed core and current core for 16-voice Unison Square, Saw, and strong FM showed nearly unchanged energy share above a simple 2 kHz high-pass proxy (for example, Square 0.092 vs 0.092, Saw 0.185 vs 0.185). This does **not** prove perceptual equivalence or exclude convolution/IR effects, but does not support a blanket new high-cut in the dry oscillator. Default Sine/Saw Unison did not engage either limiter; 16-voice Square engaged the source soft limit for about 12% of frames and the final limiter recovered between recurrent peaks. Shortening final release from 60 to 8 ms changed strong-FM RMS only modestly, so release alone is not a well-supported clarity fix.

The first controlled pair was generated in ignored `work/clarity-ab` before D-010: 3 s, 48 kHz/24-bit stereo, Saw/Harmonic/16 voices, Base 220 Hz, modulation/convolution Off, identical RMS 0.20. A used -9 dB/oct Spectral Slope; B tested -6 dB/oct. Their measured 2 kHz high-pass energy shares were about 0.280 and 0.344, with peaks about 0.696 and 0.849. This is a **candidate**, not an approved default change. Ask which waveform, stack, count, modulation and convolution settings exhibit the user's perceived dullness, then compare the relevant path with matched-loudness A/B and listening before changing production DSP. The effect of imported IR spectral balance and source loudness remains a separate later investigation.

The user heard B as more detailed and spatial, while noting left/right level differences and a fine high-frequency "furry" texture that might sound messy to some listeners. The original files measured A left/right RMS 18.46 dB apart and B 12.40 dB apart; B's right-channel RMS approximately doubled relative to A while left RMS stayed similar. This identifies an unintended interaction of index-ordered pan and negative Spectral Slope, not proof that the extra high-frequency texture is aliasing.

The alternating-pan candidate was rendered to `work/clarity-ab-balanced` for a direct A/B; the historical original-pan files remain in `work/clarity-ab`, and the comparison script again targets that original-pan directory. Balanced A/B measured about 1.34/1.79 dB left/right RMS difference at -9/-6 dB/oct, while the -6 candidate's high-pass share remained about 0.339. The user heard the balanced version as thicker, nearer, more uniform, and less musically compelling than the original. This is a **rejected sonic change despite better numerical channel balance**. The original low-to-high left-to-right progression was restored; preserve the user observation for any future standalone pan design. Production slope remains -9, and the finer Saw high-frequency texture plus imported-IR variance remain separate open investigations.

## 2026-10-01 Two-Voice-Pair Glissando (Approved)

The user reported strong leftward headphone imaging while gliding Base Freq from about 2900 to 110 Hz, and proposed grouping adjacent partials in pairs or triples. ## 2026-10-02 Convolution Level Diagnosis (Controlled Synthetic Test)

The user reported distortion/peaks with some loud imported files and with low-low or high-high source/Base Freq combinations, while opposite-band combinations can sound attractive. `tests/convolution-diagnostic.html` probes the existing native `ConvolverNode(normalize=true)` and 50% product Dry/Wet law without changing production DSP. Browser OfflineAudioContext at 48 kHz: 0.5 s sine oscillator at 0.5 peak, 2 s exponentially decaying sine IR (0.35 s decay), matching or opposite 100/3000 Hz bands. IR amplitude was varied from 0.1 to 0.8. These are intentionally narrow-band resonators, not representative music recordings or the user's unavailable file.

Uniformly scaling the IR by 8x produced identical wet results in this test, so file peak amplitude alone is not a sufficient explanation under native IR normalization. Matching 100/100 Hz or 3000/3000 Hz yielded wet peak about 17.42 and 50% mixed peak about 12.32 before the final limiter; the limiter reduced gain on about 65.7-65.8% of output frames, up to 92.77% at worst. Opposite-band 100/3000 Hz or 3000/100 Hz had wet peak at most 0.007 and no limiter engagement. This supports frequency-selective buildup as a plausible mechanism and shows why a peak-only safety limiter can be audibly overworked. It does not establish that the user's file has these values, that all real IRs are scale-invariant under every browser, or that high-frequency roughness is definitely not aliasing.

Next: measure the actual named file with the user's curve/settings, separately capturing dry, native wet, mixed pre-limiter, final peak, limiter gain-reduction duration, and comparable listening levels. Do not tune an automatic wet gain or filter until that evidence is available; preserve attractive cross-band results for comparison.
