# Static Resynthesis v1

Snapshot: 2026-09-30. This documents implemented web behavior, not approved sonic parity for a future Standalone engine. `OSCILLATOR`, `RESYNTHESIS`, and `CONVOLUTION` are mutually exclusive sound-generation modes. OSCILLATOR is the default; CONVOLUTION is the existing oscillator plus optional local IR, not file playback. Switching modes stops the current sound but keeps the existing AudioContext/Worklet. The oscillator and resynthesis curves are stored separately in memory; neither is a persisted preset.

## Analysis and original data

Open Sound File decodes a local audio file at 48 kHz. The web UI caps input files at 32 MiB. It uses at most 30 seconds centered in the decoded file and selects the channel with the highest sampled energy, avoiding cancellation from opposite-polarity stereo channels. Decode is asynchronous; chunked sample copying yields to the UI; spectral work runs in a dedicated Worker. Analysis is static: it is not source playback, frame tracking, or time-varying spectral resynthesis.

The Worker averages the power of up to nine 8192-point Hann FFT windows across the central 80% of the analyzed segment, ignoring windows with near-zero energy. A local-maximum peak must be at least -50 dB in power relative to the strongest in-range bin and be separated from previously selected peaks by at least `max(12 Hz, 1.5 FFT bins)`. Log-power parabolic interpolation estimates sub-bin frequency. Candidates are chosen by strength up to 32 or 64, then stored in ascending frequency order. Sparse material may yield fewer than the selected maximum; missing partials are **not fabricated**. The estimate labeled Fundamental is the lowest selected significant peak, not a robust pitch tracker. Analysis choices are initial engineering settings, not musician-approved thresholds.

`AnalysisResult` retains source metadata, analysis settings, estimated fundamental, actual partial count, and for each partial: one-based index, unquantized frequency Hz, measured FFT amplitude, amplitude relative to the strongest selected peak, harmonic ratio relative to the estimate, and cents deviation from the nearest integer harmonic. The original result is retained independently of the curves. New file import resets resynthesis curves to their neutral defaults; re-analyzing the same file at another partial count retains edits. The current web app keeps the decoded analysis segment in memory to permit reanalysis; it has no project serialization or file-reference policy.

## Transformation and synthesis

Each selected peak drives one sine oscillator with continuous phase. At neutral settings, its measured frequency ratio and relative amplitude are preserved before common safety normalization. Base Freq scales every partial frequency relative to the estimated fundamental; its current editor remains 20-4000 Hz. For an estimate outside that editor range, the neutral anchor is clamped to the range while the original partial frequencies remain the initial output. Deviation defaults to zero and adds the existing deterministic per-index partial bend when raised. Spectral Slope defaults to **0 dB/oct in Resynthesis** and reweights partial amplitudes; it is the first-version amplitude-distribution curve, not per-partial editing. The OSCILLATOR mode retains its own -9 dB/oct default and independent curves. UI edits never overwrite AnalysisResult.

All active partials below `0.48 * sampleRate` participate. Their amplitudes receive the common `0.82 / max(1, sum(abs(amplitude)))` scale, index-distributed stereo pan, soft limiter, 8/12 ms source-edge fade, and output safety path. The same `renderFrame` dispatch serves AudioWorklet, 48 kHz/24-bit WAV, and dry FFT observation. High-frequency omission changes the audible voice count. This is a static oscillator bank: no original transients, noise bed, moving partial trajectories, or exact source reconstruction are promised.

## Web/native boundary and open tests

Portable concepts: AnalysisResult schema, peak-selection policy, unquantized ratios, neutral transformation contract, separate original/transformed data, normalized curves, oscillator-bank behavior, and expected mode identity. Web-specific pieces: browser decoder, Worker, AudioWorklet, Canvas controls, file chooser, and Web Audio output. A native implementation may replace them but must compare output and listening results before claiming equivalent sound.

Automated tests cover three inharmonic peaks, sparse versus rich 32/64 selection, unchanged source data after curves, curve-responsive voices, and 24-bit WAV. Browser checks used synthetic 3- and 64-partial WAVs on 2026-09-30: file decode, analysis, 64 active voices, Play, FFT completion, UI WAV completion, and Convolution control visibility. The browser download event timed out, but the downloaded 1-second file was independently found and `ffprobe` confirmed stereo `pcm_s24le` at 48 kHz. CPU budget, underruns, long encoded files, native-rate fallback, complex real-world material, perceptual similarity, and edge-case pitch estimation remain unverified. Record those in `KNOWLEDGE_PRESERVATION.md` before fine-tuning thresholds.
